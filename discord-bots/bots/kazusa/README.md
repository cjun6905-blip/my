# 冬马和纱

这是当前 Bot 的公开源码快照。凭据、真人/服务器身份绑定已替换为示例值；运行数据库、聊天内容、学习语料、自动长期记忆、日志、密钥和历史备份不在仓库中。

`snapshot-manifest.json` 逐文件记录运行时原始 SHA256、公开文件 SHA256 和模板化类别。`runtime.example.json` 记录运行时的基础镜像、启动命令、资源限制以及经过处理的环境设置。`requirements.snapshot.txt` 记录当时安装的 Python 包版本。

`Dockerfile.snapshot` 使用部署主机已经存在的基础镜像，再覆盖本目录的源码与资源，保留该镜像的系统依赖和证书修复。它不是完整容器镜像备份；迁移到没有该镜像的机器时，需要先根据原框架和依赖记录准备基础镜像。

初次准备可在此目录执行 `python ../../tools/init_instance.py .`，再在生成的私有文件中填写独立 Discord Token、模型凭据、媒体凭据和实际服务器/用户 ID。`compose.example.yaml` 是配置模板，按本机服务和数据库情况调整后使用。原文件中的 `0` 身份占位符以及空的可信 Bot 列表必须配置；代码中的固定身份绑定也需要按部署目标恢复。不要用公开模板覆盖已有生产配置和数据库。

轻量实例在同一主机共享 `discord-bots/.runtime/fleet`，保留模型、识图、生图和语音的跨实例资源保护。传统框架还需要其原有 PostgreSQL/配套服务，相关源文件和配置参考保留在各自目录中。
